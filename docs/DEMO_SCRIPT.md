# Nightjar demonstration recording plan

Target length: 2 minutes 45 seconds, with a hard stop before 3 minutes. This is a script for a future real recording. No video or screenshot has been fabricated. Recording is blocked until a supported rendered preview is available; public upload also needs authorization.

Keep the simulation disclosure visible. Record the actual application and actual proof command. Do not edit separate states together to imply an uninterrupted live transaction, live travel inventory or Alexa device interaction.

## 0 00 to 0 25 — A connected problem

Screen action: Show the starting app and run the default request at $300 and 01:00.

Narration:

“A cancelled late-night flight can break the whole journey. The hotel may stop expecting you, and the last ride depends on your new arrival. Nightjar coordinates that recovery as one connected plan. This is an independent Alexa+ concept. Travel suppliers and the conversation are simulated.”

## 0 25 to 0 50 — Review before changes

Screen action: Show $234 and 00:45. Briefly expand rejected alternatives. Open the approval dialog and show the exact version and total before approving.

Narration:

“The plan protects the prepaid room, replaces the flight and arranges the final transfer. A cheaper flight misses the arrival deadline. The room hold is still proposed here. Nothing changes until this exact version and total are approved.”

## 0 50 to 1 30 — Recover an unknown outcome

Screen action: Inject Ground booking response lost, then execute. Show confirmed hotel/flight and unknown transfer. Reload, reconcile and display the final receipt.

Narration:

“Now the transfer service saves the booking, but its response is lost. The hotel and flight already succeeded. Nightjar saves that uncertainty instead of blindly creating another reservation. After reload, it checks the existing request key, retrieves the receipt and finishes. The evidence shows one transfer creation and one reconciliation lookup.”

## 1 30 to 2 00 — A changed price changes consent

Screen action: Reset, build and approve; inject Transfer price changes; refresh to $269 and a new version. Do not execute automatically.

Narration:

“A changed quote needs fresh consent, even when it is still within the budget. The previous approval is invalid. The updated plan costs 269 dollars and waits for review. Existing ticket rights and the prepaid reservation remain protected.”

## 2 00 to 2 30 — Show the real protocol

Screen action: Run npm run demo:proof. Keep its automated-fixture disclosure visible. Show initialization, the three tool names, approval denial and repeat-safe recovery.

Narration:

“The MCP layer is real. The official SDK negotiates version 2025-11-25 over Streamable HTTP. These calls actually execute. The tool surface has no approval tool. This automated proof uses labelled synthetic approval fixtures, so it does not claim a real person's consent.”

## 2 30 to 2 45 — Close with the boundary

Screen action: Return to the final app state and show the simulation labels.

Narration:

“Nightjar demonstrates a bounded recovery that survives interruption. The next steps are rendered-browser validation and real integration work. No live Alexa, language model, payment or travel-provider connection is claimed.”

## Recording checklist

- Use actual runtime footage, not the read-only HTML export as a substitute for a working demo
- Do not show private account details, credential prompts, filesystem secrets or unrelated projects
- Retain the failure, reload and recovery transitions so their ordering is verifiable
- Use no third-party music, logo treatment or footage without permission
- Export under three minutes, inspect the actual video, then obtain the necessary upload/publication authorization
- A CLI transcript and a prepared script do not complete the video requirement
